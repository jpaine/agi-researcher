## Threats
- Synthetic / free Nebius SWE-agent traces ≠ enterprise org traffic
  - Why it bites: External validity; violations and tooling differ from real org environments; cards may overfit to demo-style actions.
  - Prebuttal in draft: Uses public SWE-agent traces; cards are tool-agnostic with dsl clauses; no enterprise logs claimed.
  - Fix: State explicitly in Methods §1.1/Limitations that this is a v0 offline proxy; restrict claims to relative detection under these traces. Add 2–3 orthogonal seeds of public traces (e.g., two different repos/tasks) to reduce overfitting. If not feasible, narrow in writeup and keep Angle 3 as backup repository artifact.
- Author-as-human review bias
  - Why it bites: Same person defines cards, labels gold, and reviews escalations → expectancy and consistency bias inflate “cards win.”
  - Prebuttal: Two-pass labeling with 72h washout; attention checks; blinding to condition identity.
  - Fix: Tighten blinding: hide queue risk_score in the UI; randomize queue order within priority bands. If a second in-lab reviewer is available for ≥25% of test reviews, add blinded replicate slice; otherwise preregister that author is the sole reviewer and report attention-check performance.
- SLM ≤8B choice drives the gap
  - Why it bites: If the effect is actually “structure helps small models,” not “cards as features,” reviewers will question generality.
  - Prebuttal: Same model/provider across conditions; effect is measured relatively.
  - Fix: Keep ≤8B as constraint but add a tiny sanity check on dev: swap between two ≤8B models (e.g., Llama-3.1-8B vs Mistral-7B) to ensure the direction isn’t model-idiosyncratic. Report only as a qualitative check; do not broaden the claim.
- Cards add tokens → unfair compute vs baseline
  - Why it bites: Cards condition may process fewer steps before token cutoff; current metric normalizes on different denominators, biasing comparisons.
  - Prebuttal: Budgets track tokens/time; fixed step order with random seed.
  - Fix: Precompute N_target on dev as the minimum throughput across A–C, then enforce the same step subset for all SLM conditions on test (truncate to N_target). Rewrite §6.1/§7.2/§8.2 accordingly. Keep human-minute budgets identical.
- Prose baseline under-prompted
  - Why it bites: If prose is a wall of text, the comparison becomes “structure vs slop,” not “structure vs same content.”
  - Prebuttal: Programmatic generation from YAML; same content guaranteed.
  - Fix: Add lightweight structure-preserving formatting to prose (headings, bullet-like separators) and mirror the instruction text so both A and B reference specific “policy artifacts.” Include identical examples and card_ids rendered as tags in prose to remove naming advantage.
- Label leakage / overfitting to inject patterns
  - Why it bites: EDA keyword probes and escalate_when tuning could bake in test patterns.
  - Prebuttal: Dev/test split at trajectory level; calibrations on dev only; freeze before test.
  - Fix: Lock a written rule that test split receives zero escalate_when edits; log git SHAs; prohibit using test-set weak labels. In reporting, list 2–3 examples where probes misfire to show non-triviality.
- Nebius free-tier overlay fairness
  - Why it bites: If overlay differs across conditions, iso-cost comparability is undermined.
  - Prebuttal: “All SLM conditions use identical provider/model; disclosure of overlay is logged.”
  - Fix: Pin provider/model/version; run conditions back-to-back within a narrow window; capture rate limits/throughput in logs. If throttling differs across runs, re-run to balance or reduce N_target.
- Scope creep into Magentic / Ctrl-Z / OCL / ToolGuard / One-Human-N / SCHEME
  - Why it bites: Reviewers may perceive novelty inflation or wrong foil.
  - Prebuttal: Non-claims listed; irreversibility heuristic listed as optional foil.

## Reviewer attacks + replies
- “Isn’t this just Magentic ActionGuard with YAML?”
  - Reply: No. We evaluate org-policy cards as structured escalation features for iso-cost human+SLM oversight on multi-step SWE traces. We do not claim irreversibility UI/product contributions. The primary comparator is the same policy content in unstructured prose; the delta isolates structure, not UI heuristics.
- “How is this not ToolGuard / OCL?”
  - Reply: ToolGuard/OCL target deterministic pre-tool control layers or full governance stacks. We study detection under fixed oversight budgets with human escalation, not preemptive tool gating or economic control layers. Our cards carry SoD/spend/egress semantics to improve escalation, not to synthesize guard code.
- “Iso-cost is fake if Nebius is free.”
  - Reply: Iso-cost is defined as metered judge tokens/time plus human minutes, with the same provider/model across conditions and explicit token/time caps. We disclose the free-tier overlay and enforce identical step subsets across SLM conditions to keep compute comparable.
- “N is too small / labels are author-made — so what?”
  - Reply: This is a workshop pilot with free public traces. We control for author bias via blinded queues, attention checks, and a two-pass label protocol on a held-out test split. The claim is relative (Cards vs Prose) under iso-cost, not an absolute SOTA claim; the setup is sufficient to test that narrow hypothesis.
- “Why isn’t this a main-conference methods paper?”
  - Reply: It isn’t positioned as one. The contribution is a narrow ablation under strict budget constraints suitable for a workshop. If the ablation is flat, we pivot to releasing a small, reusable OpenControl-Bench-Lite artifact rather than over-claiming.
